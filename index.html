Deep Learning & Multi-Label Classification Grade: 100/100 Marks

Neural Network Learning Lab — Multi-Label Industrial AI Dashboard

Practical Application Development, Interactive Architecture & Controlled Empirical Analysis

3 → 5 → 4 → 2 Topology Optimizer: SGD (α = 0.001 – 0.1) Loss: Binary Cross-Entropy ReLU & Sigmoid Activations 180 Industrial Observations R Shiny & Streamlit

Industrial Problem Scenario

Models an industrial condition-monitoring environment where factory machinery logs three continuous sensor signals: Temperature (°C) ($x_1$), Vibration (mm/s) ($x_2$), and Pressure (kPa) ($x_3$). The network simultaneously predicts two independent warning indicators: overheat_alert and fault_alert.

Crucial Finding: Why Multi-Label (Dual Sigmoids) vs Softmax?

In real machinery, overheating and mechanical faults are physically distinct, independent failure modes. Across 180 observations, all permutations exist: (0,0)=96, (1,0)=27, (0,1)=25, and (1,1)=32 simultaneous double alerts. Softmax computes a normalized distribution ($\sum p_k = 1.0$), falsely assuming mutual exclusivity (meaning rising temperature would artificially depress fault probability!). Two independent sigmoid neurons with Binary Cross-Entropy (BCE) loss allow both alerts to trigger concurrently.

Figure: Fully Connected 3-5-4-2 Feedforward Topology Full View

Visual representation of the 3-5-4-2 network showing layer connectivity, weight matrices ($3\times5$, $5\times4$, $4\times2$), and bias vectors.

Input Layer 3 Continuous Sensor Units ($x_1, x_2, x_3$)
Hidden Layer 1 5 Neurons (ReLU / Sigmoid switchable)
Hidden Layer 2 4 Neurons (ReLU / Sigmoid switchable)
Output Layer 2 Independent Sigmoids ($\hat{y}_1, \hat{y}_2 \in (0, 1)$)
Optimization Stochastic Gradient Descent (SGD)
Loss Function Multi-Label Binary Cross-Entropy (BCE)

Mathematical Formulation

Forward propagation computed from mathematical first principles across weight matrices and bias offsets:

Layer 1 (Hidden 1)
Z(1) = X · W(1) + b(1),   A(1) = g(Z(1))
W(1) ∈ ℝ3×5,   b(1) ∈ ℝ5,   g ∈ {ReLU, Sigmoid}
Layer 2 (Hidden 2)
Z(2) = A(1) · W(2) + b(2),   A(2) = g(Z(2))
W(2) ∈ ℝ5×4,   b(2) ∈ ℝ4,   g ∈ {ReLU, Sigmoid}
Layer 3 (Output Layer)
Z(3) = A(2) · W(3) + b(3),   Ŷ = σ(Z(3))
W(3) ∈ ℝ4×2,   b(3) ∈ ℝ2,   σ(z) = 1 / (1 + e-z)
Loss Function (Binary Cross-Entropy)
Loss = − (1/m) ∑ [ yk ln(Ŷk) + (1 − yk) ln(1 − Ŷk) ]
Parameter updates: θ ← θ − α ∇Loss (SGD)

Empirical Comparison Across All 8 Configurations

Final training vs validation loss for all 8 experiment runs, highlighting learning rate speed and activation vanishing gradients.

Learning Rate Dynamics: Does higher LR always mean faster convergence?

Finding: No. While increasing LR from 0.001 to 0.1 reduced training loss from 0.7789 to 0.5148 by overcoming underfitting, excessively high learning rates (α > 0.5) trigger gradient overshoot, oscillation across ravines, and eventual divergence (Loss → ∞). Input standardization strictly bounded variance to keep 0.1 stable.

Hidden Activations: Why does ReLU outperform Sigmoid?

Theoretical Cause: Sigmoid derivative saturates: σ′(z) = σ(z)(1 − σ(z)) ≤ 0.25. Backpropagating through 2 hidden layers attenuates gradients by factors ≤ (0.25)2 = 0.0625 (vanishing gradient problem). Early weights freeze. Conversely, ReLU′(z) = 1 for all z > 0, sustaining maximum gradient magnitude and convergence velocity.

Epoch Scaling: Does increasing epochs always improve generalization?

Finding: No. Scaling from 20 to 100 epochs reduced validation loss from 0.8356 to 0.5972 (test accuracy jumped from 61.1% to 70.4%). While 300 epochs reached 0.5485, training beyond this threshold risks memorizing noise, evidenced when training loss drops while validation loss turns upward (ΔL_val > 0), establishing the need for early stopping.

Strict Zero-Leakage Preprocessing Protocol

To ensure rigorous industrial machine learning standards, standardization parameters (mean μ and standard deviation σ) were derived strictly from the 126 training instances and applied downstream to validation, test, and live prediction inputs.

Reproducible 70% / 15% / 15% Data Split

Fixed seed (seed = 42) partitioned the 180 records into: Training: 126 records (70%), Validation: 27 records (15%), and Test: 27 records (15%). Identifier machine_id was strictly excluded from features.
